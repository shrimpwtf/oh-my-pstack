### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `~/.agents/skills/poteto-mode/scripts/worktree-audit.sh` (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed conventional path can miss a worktree created elsewhere by the active host (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, and PR state, then suggests a bucket.
2. The bucket is advice, not permission. Known active sessions and durable work records are the real artifact. Get the session identifiers from the active adapter or the user and audit them against the classifier; explorer sessions may read only matching workspace-scoped history to extract worktree paths or HEADs. Any referenced worktree is held from deletion: the `KEEP_ACTIVE` bucket means preserve it, not that current execution was proved, even if the heuristic says stale. The script's history cross-check is only a warning: it can identify recorded use, not current process liveness; no match proves nothing because the path may be implicit.
3. Verify usage before deleting. For every `review` row or uncertainty, use the active adapter's live-status surface to establish whether an actor can still write. Interpret history and transcripts only according to the adapter's documented evidence contract; do not treat them as proof of current activity unless the adapter guarantees that. If current state or safe cancellation cannot be established, mark it unknown and keep the worktree.
4. Pause on irreversible loss or protection. `wip:N` is N tracked uncommitted edits. `scratch:N` is N untracked files, not proof they are disposable. `locked:<reason>` is an intentional Git protection and always holds. Show every changed and untracked file and get an explicit decision before removing either kind. A lock requires a separate explicit unlock decision. Clean, unlocked, merged, and proven not-in-use may proceed.
5. Prune the confirmed set recoverably. Move each approved worktree directory to Trash with `trash <path>`, then run `git worktree prune`. Do not run `git worktree remove --force`, which can destroy untracked files before Trash sees them. Branch refs survive, and the trashed directory remains recoverable until Trash is emptied. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`; package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
